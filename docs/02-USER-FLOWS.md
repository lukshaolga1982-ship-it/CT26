# 02. Пользовательские сценарии

## A. Первый учитель

1. Администратор создаёт пользователя или подтверждает email.
2. Сервер назначает custom claim `teacher: true`.
3. Учитель входит и создаёт профиль.
4. Создаёт класс и получает приглашение.
5. Отправляет код или ссылку учащимся.

## B. Присоединение ученика

1. Ученик открывает `/join/{code}`.
2. Если не вошёл — регистрируется по email/password или разрешённому провайдеру.
3. Видит имя учителя/класса, но не список участников.
4. Подтверждает вступление.
5. Callable Function транзакционно проверяет код, срок, лимит и создаёт membership.
6. Повторное принятие того же приглашения идемпотентно.

Ошибки: неверный/истёкший/отозванный код, лимит использован, пользователь уже состоит в классе.

## C. Создание назначения

1. Учитель выбирает класс.
2. Выбирает тип: полный вариант, блоки, вручную или случайно.
3. Для случайной подборки задаёт фильтры и seed; сервер фиксирует конкретные `questionId`.
4. Устанавливает сроки, таймер, попытки и показ ответов.
5. Предпросматривает работу без доступа ученика к ключам.
6. Публикует; после публикации состав версии неизменяем.

## D. Решение

1. Ученик открывает назначение.
2. Сервер проверяет окно доступности и лимит, создаёт attempt.
3. Клиент получает только публичные данные заданий.
4. Ответы автосохраняются.
5. Ученик сдаёт; функция блокирует попытку, проверяет и записывает результат.
6. Интерфейс показывает разрешённый объём обратной связи.

## E. Истечение времени

Клиент показывает таймер, но сервер является источником истины. Ответы с временем после `expiresAt` отклоняются. Фоновая функция может закрывать зависшие попытки; при следующем запросе истёкшая попытка также закрывается лениво.

## F. Повтор ошибок

1. Ученик выбирает завершённую попытку.
2. Если разрешено, сервер создаёт `retry_mistakes` только из ошибочных заданий.
3. Новая попытка не меняет исходный результат.
4. Учитель видит прогресс повторной тренировки отдельно.

## G. Ручной пересмотр Б

1. Учитель фильтрует ответы `needsReview`.
2. Видит исходный и нормализованный ввод, допустимые ответы и контекст.
3. Меняет решение, указывает комментарий.
4. Сервер пересчитывает итог в транзакции.
5. В audit log сохраняются старое/новое решение, UID и время.

## H. Экспорт

Учитель выбирает класс/назначение/период. Сервер проверяет право, формирует файл и выдаёт краткоживущую ссылку либо поток загрузки. Экспорт содержит только данные этого учителя.
