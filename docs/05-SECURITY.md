# 05. Безопасность, роли и приватность

## Матрица доступа

| Ресурс | Ученик | Учитель-владелец | Администратор |
|---|---:|---:|---:|
| Свой профиль | R/U | R/U | R |
| Класс | R при membership | CRUD свой | R |
| Участники класса | ограниченное R | R/удаление | R |
| Приглашение | принять через Function | CRUD через Function | R |
| Опубликованные задания назначения | R | R | CRUD банка |
| Приватные ключи | запрещено | запрещено напрямую | серверные процедуры |
| Свой черновик попытки | R/U до дедлайна | R после сдачи | R |
| Чужая попытка | запрещено | R для своего класса | R |
| Результат/ручной review | R свой | R/review через Function | R |
| Audit log | запрещено | ограниченно свой | R |

## Обязательные принципы

1. Default deny в Firestore и Storage Rules.
2. Клиент не назначает роли и не изменяет `teacherId`, `studentId`, баллы, статус сдачи или timestamps.
3. Ключи полностью недоступны клиентским SDK, включая учителя; учителю интерфейс выдаёт необходимые данные через функцию.
4. Проверка ownership выполняется и в rules, и в Functions.
5. Все входы валидируются, строки/массивы имеют лимиты размера.
6. App Check включается для Web и Functions; enforcement — после тестового периода.
7. Секреты хранятся в Secret Manager/GitHub Secrets.
8. GitHub secret scanning и Dependabot включены.

## Приглашения

- криптографически случайный код не менее 128 бит либо одноразовый token;
- срок действия, отзыв, лимит использований;
- rate limit по UID/IP/App Check token;
- код не писать в логи;
- принятие транзакционно;
- запрещено перечислять действующие приглашения ученику.

## Защита попыток

- start/submit — серверные функции;
- дедлайн и таймер проверяются сервером;
- status transition только по конечному автомату;
- idempotency key для сдачи;
- ответ может изменяться только владельцем `in_progress` attempt;
- размер ответа и допустимый тип ограничены;
- после сдачи документ блокируется rules.

## Персональные данные

Хранить минимум: имя/псевдоним, email, принадлежность к классу, результаты. Не собирать дату рождения, адрес и телефон без отдельной необходимости. Опубликовать политику конфиденциальности, сроки хранения, контакты ответственного и процедуру удаления/экспорта данных. Для несовершеннолетних проверить местные требования и основание обработки.

## Шаблон правил

Файл `firebase/firestore.rules.template` — стартовый каркас, не готовая гарантия безопасности. Перед production нужны emulator tests на разрешённые и запрещённые действия.

## Угрозы для проверки

- ученик подменяет UID/classId/teacherId;
- читает ключ по предсказуемому пути;
- сдаёт после дедлайна, меняя часы браузера;
- повторно вызывает submit;
- принимает приглашение сверх лимита;
- видит результаты другого класса;
- учитель обращается к чужому классу;
- XSS через prompt/displayName;
- CSV injection при экспорте (`=`, `+`, `-`, `@` в начале ячейки);
- утечка `.env`, service account JSON или приватных ключей в GitHub.
