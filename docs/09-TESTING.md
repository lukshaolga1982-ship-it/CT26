# 09. Стратегия тестирования

## Unit

- 63 значения шкалы 0–62;
- scoring A/B и максимум 62;
- проценты неполных работ;
- нормализация Unicode, регистра, пробелов, апострофов и дефисов;
- несколько accepted answers;
- политики показа ответов;
- вычисление expiry/due date;
- генератор блоков и случайной подборки с seed.

## Firestore Rules (Emulator)

Проверить allow/deny:

- ученик читает только свои назначения/попытки;
- не читает чужого ученика;
- не читает `privateAnswerKeys`;
- не пишет баллы, UID, статус и серверные даты;
- учитель читает только собственный класс;
- учитель не меняет чужое назначение;
- опубликованный состав нельзя изменить клиентом;
- неаутентифицированный доступ запрещён.

## Functions integration

- принятие действующего/истёкшего/отозванного приглашения;
- гонка за последний invite use;
- старт до открытия/после дедлайна;
- лимит попыток;
- сдача дважды с одним и разными idempotency keys;
- сдача после expiry;
- подсчёт полного и частичного теста;
- teacher review с пересчётом и audit;
- feedback для всех политик;
- случайная подборка не содержит дублей.

## E2E Playwright

1. Администратор назначает учителя.
2. Учитель создаёт класс и приглашение.
3. Ученик регистрируется и вступает.
4. Учитель публикует полный тест.
5. Ученик решает и сдаёт.
6. Учитель видит результат/ошибки.
7. Учитель пересматривает Б.
8. Ученик видит обновление согласно policy.
9. Экспортируется ведомость.
10. Ученик повторяет ошибки.

Отдельно: мобильный viewport, offline/reconnect, refresh посреди попытки, две вкладки, доступность через axe.

## Контентные тесты

Для каждого из 10 вариантов валидатор подтверждает 40 заданий, номера А1–А18/Б1–Б22, максимум 62, наличие ключей и statuses. Итого ожидается 400 вопросов до возможных особенностей структуры stimuli.

## Нагрузочные проверки

Смоделировать одновременную сдачу класса (например, 30–100 учеников), оценить Firestore contention, latency функции и стоимость. Не использовать один горячий документ-счётчик на все ответы.

## Definition of Done

Функция готова, если есть типы/валидация, unit/integration tests, обработка ошибок, правила доступа, логирование без PII, документация и успешный staging smoke test.
