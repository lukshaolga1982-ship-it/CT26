# 08. Оцифровка и импорт сборника

## Исходные данные

Анализ PDF подтвердил 44 сканированные страницы и 10 вариантов:

- ЦЭ: варианты 1–5;
- ЦТ: варианты 1–5;
- каждый вариант: А1–А18 и Б1–Б22.

OCR — только черновик. Ошибки особенно вероятны в `I/l/1`, апострофах, дефисах, номерах, таблицах ключей и границах текстов.

## Конвейер

1. Сохранить исходный PDF вне публичного GitHub.
2. Рендерить страницы 250–300 DPI.
3. OCR языками `eng+rus`.
4. Разделить на варианты, stimuli и вопросы.
5. Создать публичные JSON без ключей.
6. Создать приватные JSON ключей вне публичной папки.
7. Проверяющий №1 построчно сверяет prompt/options с изображением.
8. Проверяющий №2 независимо сверяет ключи и номера.
9. Валидатор проверяет схему, дубли, диапазоны и состав.
10. Импортировать `verified`; публиковать только `published`.

## Статусы

- `ocr_draft` — результат распознавания;
- `reviewed` — текст сверил один человек;
- `verified` — текст и ключ независимо сверены;
- `published` — разрешён для назначения;
- `rejected` — требует повторного ввода.

Текст и ключ имеют отдельные статусы. Задание не публикуется, пока оба не `verified`.

## Идентификаторы

Рекомендуемый ID: `ce-v01-a01`, `ct-v05-b22`. Stimulus: `ce-v01-s01`. ID неизменяем; исправления увеличивают `contentVersion`/`keyVersion`.

## Типы заданий

Минимально:

- `single_choice` — часть А;
- `short_text` — часть Б;
- `shared_text_single_choice` — вопрос со stimulus;
- `shared_text_short_text` — Б со stimulus.

Если в задании требуется последовательность символов, всё равно хранить как `short_text` с явно заданной нормализацией.

## Проверки полноты каждого варианта

- ровно А1…А18 без пропусков/дублей;
- ровно Б1…Б22 без пропусков/дублей;
- `points=1` для А и `points=2` для Б;
- каждый choice имеет уникальные option IDs;
- каждый вопрос имеет ключ;
- ссылки на stimulus существуют;
- страницы источника заданы;
- полный максимум равен 62;
- блок определяется однозначно.

## Хранение в Git

Можно коммитить:

- проверенный публичный текст заданий при наличии прав;
- schemas, manifests, блоки и шкалу;
- фиктивные примеры.

Нельзя коммитить в публичный репозиторий:

- service account JSON;
- `.env` production;
- приватные ключи ответов;
- исходный PDF/сканы без права на распространение;
- персональные данные.

## Импорт

Скрипт должен иметь режимы `--dry-run`, `--project`, `--public`, `--private`, проверять JSON Schema и checksum. Импорт приватных ключей запускается только доверенным администратором через Admin SDK. Каждая загрузка создаёт manifest с версиями и SHA-256.

## Исправления

Нельзя редактировать опубликованное задание так, чтобы изменилась история попытки. Создать новую версию. Если исправлен ключ, требуется отчёт о затронутых попытках и явное решение о пересчёте.
