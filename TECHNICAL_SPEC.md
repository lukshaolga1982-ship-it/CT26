# Техническое задание: интерактивные тесты ЦЭ/ЦТ по английскому языку

## 1. Цель проекта

Создать современный адаптивный сайт, на котором учащиеся могут:

- входить в личный кабинет;
- выбирать доступный тест или назначенный учителем тест;
- решать полный вариант ЦЭ/ЦТ онлайн;
- тренироваться по отдельным блокам заданий;
- сохранять ответы и продолжать незавершённую попытку;
- после завершения видеть результат в первичных и тестовых баллах;
- просматривать историю своих попыток и ошибок в пределах, разрешённых учителем.

Учитель должен иметь отдельный защищённый кабинет, в котором можно:

- регистрировать и редактировать учащихся;
- объединять учащихся в группы;
- назначать тесты и отдельные блоки;
- задавать срок выполнения и количество попыток;
- видеть результаты, ответы, ошибки и динамику каждого учащегося;
- анализировать трудные задания и блоки по ученику, группе и всему классу.

Сайт должен быть пригоден для публикации на GitHub Pages. Для авторизации, безопасного хранения данных и синхронизации использовать Firebase.

## 2. Исходные материалы

Использовать приложенные материалы:

1. `сборник цэ цт англ 2026_compressed.pdf` — основной сборник 2026 года. В нём находятся 10 вариантов тестов, задания A1–A18 и B1–B22, а также ответы в конце.
2. `+ЦТ 2025.pdf` — дополнительный материал по структуре и тематическим блокам заданий. Не добавлять задания из него в банк автоматически, если это отдельно не подтверждено учителем.
3. `60b24843-0a6b-49be-b6d5-c4578dcf2b11.png` — официальная таблица перевода 62 первичных баллов в 100 тестовых баллов для 2026 года.

Тексты заданий и ключи должны быть перенесены из PDF без перефразирования. После распознавания обязательно вручную сверить:

- номера заданий;
- варианты ответа;
- пропуски и подчёркивания;
- апострофы, кавычки и знаки препинания;
- ответы в заданиях части B;
- ключи каждого варианта.

Нельзя определять правильные ответы с помощью ИИ, если они есть в таблице ответов. Единственный источник правильного ответа — ключи в конце сборника, проверенные учителем.

## 3. Технологии

Рекомендуемый стек:

- HTML5;
- CSS3;
- JavaScript ES Modules без обязательного фреймворка;
- Firebase Authentication;
- Cloud Firestore;
- Firebase Cloud Functions с Admin SDK для защищённого создания учётных записей учащихся;
- Firebase Hosting не обязателен: интерфейс размещается на GitHub Pages;
- локальный кэш через `localStorage` или IndexedDB только для черновика текущей попытки, но не как основное хранилище результатов.

Важно: ключи ответов, права учителя и итоговые результаты нельзя доверять только клиентскому JavaScript. Ученик не должен иметь возможность получить ключи всех тестов из публичного файла репозитория или изменить свой результат через DevTools.

### 3.1. Почему одного GitHub Pages недостаточно

GitHub Pages является статическим хостингом. Он подходит для интерфейса, но не обеспечивает:

- безопасную регистрацию учащихся;
- разграничение ролей «учитель/ученик»;
- закрытое хранение ключей;
- защищённую проверку ответов;
- сохранение результатов разных пользователей.

Поэтому интерфейс размещается на GitHub Pages, а авторизация, база данных и проверка результатов выполняются через Firebase.

## 4. Роли и права доступа

### 4.1. Учитель

Учитель может:

- войти по электронной почте и паролю;
- создавать ученика: имя, фамилия, логин, временный пароль, группа;
- сбрасывать пароль ученика;
- блокировать и восстанавливать доступ;
- создавать, переименовывать и удалять группы;
- назначать полный вариант или выбранные блоки;
- задавать дату открытия, дедлайн и количество попыток;
- разрешать или запрещать просмотр правильных ответов;
- просматривать все попытки и незавершённые работы;
- открывать детальный разбор попытки;
- экспортировать результаты в CSV;
- добавлять новые тесты через подготовленный JSON-файл или редактор тестов.

### 4.2. Ученик

Ученик может:

- войти по выданным учителем данным;
- сменить временный пароль при первом входе;
- видеть только собственные данные;
- видеть назначенные и доступные тесты;
- решать полный тест или разрешённый блок;
- сохранять прогресс;
- завершать попытку с подтверждением;
- видеть собственные результаты и историю попыток;
- просматривать ошибки и правильные ответы только согласно настройкам назначения.

### 4.3. Гость

Гостевой режим по умолчанию отключить. Незарегистрированный пользователь видит только стартовую страницу и форму входа. Тесты, ключи, результаты и список учащихся гостю недоступны.

## 5. Авторизация по логину и паролю

Самостоятельная регистрация запрещена. Учитель лично создаёт каждому ученику логин и пароль.

1. Учитель нажимает «Создать ученика».
2. Указывает имя, группу, уникальный логин и временный пароль.
3. Защищённая Cloud Function создаёт аккаунт Firebase Authentication и профиль Firestore.
4. Учитель сообщает ученику логин и пароль.
5. Ученик выбирает роль «Ученик» в окне входа и входит в личный кабинет.
6. Учитель входит через отдельную роль «Учитель» и видит учительский кабинет.

Если Firebase Authentication требует email-формат, система может незаметно преобразовывать логин, например `marta7` → `marta7@students.local`. Ученик вводит только `marta7`, а не технический адрес.

Нельзя создавать ученические аккаунты напрямую из публичного клиентского кода с административными ключами.

Учитель может изменить имя и группу, сбросить пароль, заблокировать аккаунт или восстановить доступ. Ученик не может создать себе аккаунт или изменить роль.

- часть A: A1–A18, 18 заданий;

## 7. Форматы интерактивных заданий

### 7.1. Часть A

Для A1–A18 использовать выбор одного ответа из предложенных вариантов.

Требования:

- варианты ответа оформлены как большие удобные карточки или radio-кнопки;
- выбрать можно только один вариант;
- выбранный ответ хорошо заметен;
- ответ можно изменить до завершения попытки;
- для заданий с общим текстом текст постоянно доступен рядом или через закреплённую область;
- на мобильном устройстве текст и вопрос располагаются последовательно без горизонтальной прокрутки.

### 7.2. Часть B

Для B1–B22 использовать текстовое поле.

Нормализация при проверке:

- удалить пробелы в начале и конце;
- привести ответ к нижнему регистру;
- заменить повторяющиеся пробелы одним;
- унифицировать типографские и прямые апострофы;
- унифицировать разные виды дефисов и тире в обычный дефис там, где он является частью ответа;
- не учитывать регистр;
- не исправлять орфографические ошибки автоматически;
- не принимать другой ответ только на основании смысловой похожести;
- при наличии нескольких официально допустимых форм хранить массив допустимых ответов.

Ответ части B может быть словом, словосочетанием или последовательностью символов. Нормализация должна устранять только технические различия и не объединять ответы, которые лингвистически отличаются.

Учитель может вручную пересмотреть любой ответ части B: принять его, оставить неправильным либо добавить как допустимый вариант для текущего теста. Изменение применяется только к одной попытке или, после отдельного подтверждения, ко всем полностью совпадающим ответам этого теста. Сервер пересчитывает результат. В журнале сохраняются прежняя и новая оценка, учитель, дата, комментарий и область применения. Ученик видит отметку «Ответ пересмотрен учителем».

Для B9–B18, где обычно вводится лишнее слово, принимать только слово из официального ключа. Для B19–B22 принимать точную грамматическую/словообразовательную форму из ключа.

### 7.3. Общие тексты и группы вопросов

Общие инструкции, тексты для чтения, диалоги и списки слов не дублировать в каждом вопросе. Хранить их как `sharedContent` и связывать с соответствующими заданиями.

## 8. Прохождение теста

### 8.1. Режимы прохождения

1. **Полный тест A1–B22** — 40 заданий выбранного варианта, максимум 62 первичных и 100 тестовых баллов.
2. **Тренировка по блокам** — один или несколько выбранных блоков.
3. **Тест учителя** — учитель вручную составляет тест из выбранных заданий.
4. **Случайная подборка** — задания выбираются по блокам, количеству и вариантам, заданным учителем.
5. **Повторение ошибок** — отдельная тренировка только из заданий, выполненных учеником неправильно.

Для любого режима учитель может установить ограничение времени, число попыток, дату открытия, дату окончания, статус домашнего задания и правило показа правильных ответов.

Официальный тестовый балл по шкале 0–100 показывать только для полного теста A1–B22. Для остальных режимов показывать первичные баллы, доступный максимум, количество правильных ответов и процент.

Таймер рассчитывать по серверному времени. Он продолжает идти при закрытой вкладке; при истечении времени сохранённые ответы отправляются автоматически. Учитель может индивидуально добавить время ученику, а изменение записывается в журнал.

Повторение ошибок создаёт новую тренировочную попытку и не изменяет исходный результат. Задание после правильного решения исчезает из активного списка ошибок, но остаётся в истории. Учитель может назначить такую работу как обязательную.

### 8.2. Экран выбора

Ученик видит карточки:

- «Назначено учителем»;
- «Все доступные тесты»;
- «Тренировка по блокам»;
- «Мои результаты»;
- «Мои ошибки».

Карточка теста показывает название, вариант, режим, срок, разрешённое количество попыток, лучший результат и статус.

### 8.3. Экран решения

Обязательные элементы:

- название теста и варианта;
- режим: полный тест или конкретный блок;
- оставшееся время, если включено ограничение;
- индикатор прогресса;
- номера заданий с состояниями «не отвечено / отвечено / отмечено для проверки»;
- кнопки «Назад» и «Далее»;
- кнопка «Отметить вопрос»;
- автоматическое сохранение после каждого изменения;
- кнопка «Завершить тест»;
- предупреждение о вопросах без ответа;
- подтверждение окончательной отправки.

Не считать пустой ответ правильным. После окончательной отправки запретить изменение ответов в этой попытке.

### 8.4. Восстановление попытки

Если вкладка закрылась или пропал интернет:

- ответы сохраняются локально сразу;
- при восстановлении соединения синхронизируются с Firestore;
- при следующем входе появляется кнопка «Продолжить»;
- при конфликте использовать более свежую версию по времени изменения;
- завершённая попытка никогда не заменяется локальным черновиком.

## 9. Подсчёт результатов

### 9.1. Первичные баллы

- каждый правильный ответ A1–A18 = 1 первичный балл;
- каждый правильный ответ B1–B22 = 2 первичных балла;
- неправильный или пустой ответ = 0;
- частичные баллы не начисляются;
- максимум части A = 18;
- максимум части B = 44;
- общий максимум = 62.

Формула:

```text
primaryScore = correctA + correctB × 2
```

### 9.2. Официальная шкала перевода 2026 года

Не использовать линейную формулу и не вычислять тестовый балл как процент. Использовать точную таблицу соответствия:

```js
export const SCORE_SCALE_2026 = {
  0: 0, 1: 1, 2: 2, 3: 3, 4: 4, 5: 8, 6: 12, 7: 15,
  8: 18, 9: 21, 10: 24, 11: 26, 12: 28, 13: 29, 14: 31, 15: 32,
  16: 34, 17: 35, 18: 36, 19: 37, 20: 38, 21: 39, 22: 40,
  23: 41, 24: 42, 25: 43, 26: 44, 27: 45, 28: 46, 29: 47,
  30: 48, 31: 49, 32: 50, 33: 51, 34: 52, 35: 53, 36: 54,
  37: 55, 38: 56, 39: 57, 40: 58, 41: 59, 42: 60, 43: 61,
  44: 63, 45: 64, 46: 65, 47: 66, 48: 68, 49: 69, 50: 70,
  51: 72, 52: 73, 53: 75, 54: 77, 55: 79, 56: 81, 57: 84,
  58: 87, 59: 91, 60: 95, 61: 99, 62: 100
};
```

Примеры обязательных автоматических тестов:

- 0 первичных → 0 тестовых;
- 5 первичных → 8 тестовых;
- 18 первичных → 36 тестовых;
- 44 первичных → 63 тестовых;
- 62 первичных → 100 тестовых.

### 9.3. Что сохранять в попытке

Сохранять не только итоговый балл, но и неизменяемый снимок:

- ответы ученика;
- правильность каждого ответа;
- первичный балл каждого задания;
- общий первичный балл;
- тестовый балл по шкале;
- баллы отдельно за части A и B;
- результат по каждому блоку;
- дату начала и завершения;
- продолжительность;
- версию теста и версию шкалы.

Это необходимо, чтобы изменение теста в будущем не изменяло старые результаты.

## 10. Результат ученика

После полного теста показать:

- крупно тестовый балл из 100;
- первичный балл из 62;
- часть A: баллы и число правильных ответов;
- часть B: баллы и число правильных ответов;
- количество правильных, неправильных и пропущенных заданий;
- диаграмму результатов по блокам;
- длительность попытки;
- номер попытки;
- лучший результат, если попыток несколько.

В режиме разбора каждое задание имеет статус:

- правильно;
- ошибка;
- нет ответа.

Правильные ответы показываются по настройке учителя для каждого теста или назначения. Доступные варианты:

1. сразу после завершения;
2. после заданной даты или дедлайна;
3. после использования всех разрешённых попыток;
4. после ручного разрешения учителя;
5. никогда не показывать.

Отдельно задаётся объём разбора: полный разбор, только ошибочные задания или только итоговый результат. В режиме «только ошибки» учитель отдельно определяет, показывать ли правильный ответ.

## 11. Кабинет учителя

### 11.1. Главная панель

Показать:

- количество учащихся;
- активные назначения;
- незавершённые попытки;
- средний тестовый балл;
- количество работ, выполненных после срока;
- последние результаты;
- самые трудные блоки.

### 11.2. Учащиеся и группы

Таблица учащихся:

- имя и фамилия;
- логин;
- группа;
- статус аккаунта;
- последнее посещение;
- количество завершённых тестов;
- средний и лучший балл;
- действия: открыть, назначить, изменить, сбросить пароль, заблокировать.

Карточка ученика:

- история попыток;
- динамика результата по датам;
- средний результат по каждому блоку;
- повторяющиеся ошибки;
- задания, которые ученик чаще всего выполняет неправильно;
- незавершённые попытки;
- заметка учителя.

### 11.3. Результаты группы

Добавить фильтры:

- группа;
- ученик;
- тест/вариант;
- блок;
- период;
- статус попытки;
- назначение;
- первая, последняя или лучшая попытка.

Таблица результатов:

- ученик;
- тест;
- дата;
- попытка;
- A из 18;
- B из 44;
- первичный балл из 62;
- тестовый балл из 100;
- длительность;
- количество ошибок;
- статус дедлайна.

По нажатию открывается детальная попытка с каждым вопросом, ответом ученика, правильным ответом, баллом и блоком.

### 11.4. Аналитика ошибок

Учитель должен видеть:

- процент правильных ответов на каждое задание;
- количество ошибок по A1, A2 … B22;
- средний результат по каждому блоку;
- список учащихся, ошибившихся в выбранном задании;
- самые частые ошибочные варианты в части A;
- самые частые введённые ответы в части B;
- динамику ученика и группы;
- тепловую карту: строки — учащиеся, столбцы — задания, цвет — правильно/ошибка/пропуск.

## 12. Назначение работ

Учитель создаёт назначение и выбирает:

- один тест или несколько тестов;
- полный вариант или один/несколько блоков;
- тест, вручную составленный из выбранных заданий;
- случайную подборку и правила её формирования;
- повторение ошибочных заданий;
- отдельных учеников или группу;
- дату открытия;
- дедлайн;
- количество попыток;
- ограничение времени;
- учитывать первую, последнюю или лучшую попытку;
- перемешивать ли варианты ответа;
- разрешить ли возврат к предыдущим вопросам;
- режим показа разбора;
- когда показывать правильные ответы;
- показывать ли результат сразу или после дедлайна;
- считать ли назначение домашним заданием.

Для случайной подборки набор вопросов фиксируется при начале попытки, чтобы после обновления страницы он не изменялся. Учитель выбирает общий набор для всех или индивидуальную случайную подборку для каждого ученика.

Домашнее задание имеет дату окончания и статусы «не начато», «в работе», «сдано» и «просрочено». Учитель может разрешить или запретить позднюю сдачу.

Статусы назначения:

- запланировано;
- доступно;
- начато;
- выполнено;
- просрочено;
- закрыто.

## 13. Редактор и импорт тестов

Первая версия должна включать все 10 вариантов из сборника 2026 года. Дополнительно предусмотреть расширяемый формат данных, чтобы позже добавлять новые сборники без переписывания интерфейса.

- публичный контент вопросов;
- закрытые ключи в Firestore/серверной функции с доступом только учителю и проверяющей функции.

### 13.1. Статусы теста

- `draft` — видит только учитель;
- `review` — готов к ручной сверке;
- `published` — доступен для назначения;
- `archived` — сохранён в истории, но не выдаётся новым учащимся.

Перед публикацией тест должен пройти двойную проверку: структура + ключи.

## 15. Безопасность Firebase

Правила Firestore должны обеспечивать:

- ученик читает только собственный профиль, назначения и попытки;
- ученик не читает закрытые ключи;
- ученик может обновлять только ответы незавершённой собственной попытки;
- ученик не может записывать себе итоговый балл;
- завершение и подсчёт выполняются серверной функцией;
- учитель видит только созданных им учеников, группы, назначения и результаты;
- только учитель может публиковать тесты и управлять аккаунтами;
- роль нельзя изменить из браузера;
- секретные Firebase Admin credentials никогда не попадают в GitHub.

Публичный `firebaseConfig` веб-приложения допустим, но безопасность должна обеспечиваться Authentication, Firestore Rules, App Check и серверной проверкой, а не скрытием конфигурации.

## 20. Проверка качества

### 20.1. Контент

- присутствуют все 10 вариантов;
- в каждом варианте ровно A1–A18 и B1–B22;
- нет дублирующихся идентификаторов;
- все варианты ответа совпадают с PDF;
- все ключи совпадают с таблицей ответов;
- общие тексты связаны с правильными вопросами;
- каждый вопрос относится к правильному блоку.

### 20.2. Подсчёт

- A даёт ровно 1 балл;
- B даёт ровно 2 балла;
- максимум равен 62;
- шкала содержит все целые значения от 0 до 62 без пропусков;
- перевод соответствует приложенной таблице;
- блок не получает официальный тестовый балл из 100;
- пустые ответы дают 0;
- повторная отправка не создаёт двойной результат.

### 20.3. Права доступа

- ученик не видит чужие данные;
- ученик не может прочитать ключи;
- ученик не может изменить завершённую попытку;
- ученик не может подменить итоговый балл;
- заблокированный ученик не входит в систему;
- учитель может просматривать только свои группы и результаты;
- административные функции недоступны без роли учителя.

### 20.4. Устройства

Проверить минимум:

- телефон 360 px;
- телефон 390 px;
- планшет 768 px;
- ноутбук 1366 px;
- большой экран 1920 px;
- Chrome, Edge, Safari и Firefox;
- работу клавиатурой;
- потерю и восстановление интернета.

## 22. Критерии готовности первой версии

Первая версия считается готовой, если:

- учитель может войти и создать ученика;
- ученик может войти по выданным данным;
- доступны все 10 вариантов из сборника 2026 года;

## 23. Решения, которые нужно подтвердить перед разработкой

По умолчанию использовать рекомендуемые значения в скобках:

1. Регистрация подтверждена: учитель лично создаёт ученику логин и пароль.
2. Повторные попытки подтверждены: количество задаётся учителем.
3. Показ правильных ответов подтверждён: настраивается учителем для каждого теста или назначения.
4. Ручной пересмотр части B подтверждён: учитель может изменить оценку с обязательным пересчётом и журналом изменений.
5. Результат назначения при нескольких попытках: лучшая попытка (**рекомендуется**).
6. Самостоятельная тренировка вне назначений: разрешена для опубликованных тестов (**рекомендуется**), но отдельно помечается как тренировка.
7. Добавлять ли задания из `+ЦТ 2025.pdf`: по умолчанию нет, использовать файл только как справочник структуры.
8. Пояснения к ошибкам: поле предусмотреть, но не генерировать пояснения автоматически (**рекомендуется**).

## 24. Важное требование к реализации

Не начинать массовый перенос тестов до создания и проверки одного демонстрационного варианта. Сначала полностью реализовать Вариант 1, сверить его с PDF и протестировать на учительском и ученическом аккаунтах. После подтверждения структуры использовать тот же формат для вариантов 2–10.
